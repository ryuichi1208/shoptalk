# 設計と制約

## アプリケーション

Node.js 24以上の標準ライブラリだけで構成しています。実行時のnpm依存パッケージはありません。

- `src/app.js`：チャット受付、HTML配信、演習設定、受付記録、メトリクスを管理します。
- `src/ai.js`：定型応答、遅延、503応答を返す模擬AIです。
- `src/metrics.js`：テナントと結果別のカウンタ、応答時間のヒストグラムを公開します。
- `public/`：チャット画面と演習画面です。外部CDNは使用しません。

APIと模擬AIは同一イメージを使い、`SERVICE_ROLE` で起動するサービスを選択します。Node.jsのイベントループ上で待機するため、AI遅延中にもヘルスチェックへ応答できます。

## 状態の所有

演習設定、キュー、記録、メトリクスはAPIプロセスに保持します。模擬AIへは、APIが各要求の開始時点のシナリオを送ります。設定を変更しても、進行中の要求にはさかのぼって適用しません。

APIのレプリカは1に固定します。スケールアウトすると設定・キュー・カウンタが分散して、演習画面の意味が変わるためです。更新戦略はRecreateとし、旧版と新版が同時に受付を行う状態を避けます。APIの再起動や更新は、待機中の受付記録を失います。

直近100件の応答時間、直近30件のイベント、直近20件の完了記録だけを保持します。チャット本文やトークンはログに出力しません。注文記録は実データベースへの書き込みではなく、照会ID・店舗・時刻を持つ模擬記録です。

## 制限と対処

- 入力本文は8192バイトまで、メッセージは500文字までです。
- テナント名は3種類に限定し、メトリクスのラベル数を制限します。
- APIの同時受付上限は初期値8、設定可能範囲は1〜32です。
- キュー上限は200です。実行中の要求数も予約枠として計算します。
- 再試行は0〜3回、1回の制限時間は50〜3000msです。
- 再試行の間隔は50ms、100ms、200msです。ジッタやサーキットブレーカーは未実装です。
- 縮退を有効にすると、AIへの接続前に案内を返します。通常成功とは別の結果として記録します。
- 模擬AIの同時処理上限は64です。超過時には503を返します。

模擬AIは呼び出し元がタイムアウトした後も処理を続けます。外部サービスの処理が必ずしもクライアント側のキャンセルと連動しない状況を表しています。実際のLLMの演算、トークン消費、料金、品質劣化は再現していません。

## Kubernetes

非root、読み取り専用ルートファイルシステム、権限昇格の無効化、Linux capabilityの除去、RuntimeDefault seccompを設定しています。ServiceAccountトークンはマウントしません。CPU・メモリの要求値と上限、startup/readiness/liveness probeを設定しています。

readinessとlivenessは各プロセス自身の状態を返し、依存先の正常性は反映しません。模擬AIが遅延・失敗してもAPIのPodはReadyのままです。「Podは正常でも、利用者への応答は失敗する」状況を観測できます。

設定変更APIと模擬AIの呼び出しには共通の演習用トークンを使用します。これは演習環境内の簡略な認証です。ユーザー認証、TLS終端、ネットワーク分離、実環境の認可設計は含めていません。ServiceはClusterIPとし、起動手順では127.0.0.1へのポートフォワードを使います。

## 環境変数

| 名前 | 用途 | 初期値 |
| --- | --- | --- |
| `SERVICE_ROLE` | `api` または `ai` | `api` |
| `PORT` | 待受ポート | APIは8080、AIは8081 |
| `AI_URL` | APIが接続する模擬AIのURL | `http://127.0.0.1:8081` |
| `LAB_TOKEN` | 演習設定と内部呼び出しのトークン | 必須、16文字以上 |

`npm run dev` ではトークンを自動生成します。KubernetesではSecretから渡します。
